# 个人网站操作指南

> 更新：2026-10-28。适用于当前 Quartz 5 网站。本指南为草稿，不发布到网页；按既定规则，草稿源码可以公开。

**日常顺序：修改原文 → 设置发布标记 → 检查并同步 → 本地预览 → 确认后上线 → 线上复核。**

## 1. 在哪里修改

| 用途 | 位置 |
|---|---|
| Obsidian 内容原件 | `/home/hao/Desktop/HaoLifeOS/Personal_Website/content` |
| 附件和 HTML 发布清单 | `/home/hao/Desktop/HaoLifeOS/Personal_Website/publishing/assets.json` |
| CS6515 HTML 原件 | 内容原件下的 `interactive/cs6515/` |
| 网站构建、预览与正式发布 | `/home/hao/Desktop/personal_website-quartz5` |

文章和资源清单在内容库中维护。网站目录中的 `content` 是同步副本，直接修改它会造成后续同步冲突。旧目录 `/home/hao/Desktop/personal_website` 是 v4 恢复基线，日常更新不使用它。

## 2. 更新文章与发布标记

每篇 Markdown 顶部必须明确填写布尔值 `draft`：

```yaml
---
title: My Article
tags:
  - CS
  - OMSCS
draft: false
---
```

| 标记 | 下一次构建的结果 |
|---|---|
| `draft: false` | 允许生成文章，等待正式部署后上线 |
| `draft: true` | 不生成草稿文章，不进入文章索引、sitemap 或 RSS |
| `tags` | 主题分类，不控制发布 |

`true`、`false` 不加引号。缺少 `draft` 或写成字符串会停止检查。保存原文、Obsidian Git 备份和本地同步均不会直接部署网站。

撤下已上线文章：将 `draft` 改为 `true`，再走完整的同步、预览和部署流程。移除站内链接本身不会撤下文章。

## 3. 新增 CS6515 互动 HTML

1. 将 HTML 复制到内容原件的 `interactive/cs6515/`。建议使用小写英文和连字符，例如 `np-completeness.html`。
2. 编辑 `publishing/assets.json`，在现有 `html_pages` 数组中追加条目，保留原有条目：

```json
{"path": "interactive/cs6515/np-completeness.html", "publish": true}
```

3. 编辑 [[CS6515 Graduate Algorithms]]，在英文和中文的 `.cs6515-cards` 区域各增加一张卡片。英文卡片示例：

```html
<a class="cs6515-card"
   href="interactive/cs6515/np-completeness.html"
   target="_blank" rel="noopener"
   data-router-ignore data-standalone>
  <strong>NP-Completeness</strong>
  <span>Open the interactive review</span>
</a>
```

链接从内容库根目录写起，保持上述形式，不写 Downloads 路径或 `../../`。中文区域使用对应中文标题。新互动页沿用默认英文、可切换中文的约定。

HTML 使用独立的 `publish` 开关。未准备好时登记为 `false`；入口文章设为草稿不会隐藏已批准的 HTML。撤下 HTML 时将对应 `publish` 改为 `false`，并移除或调整入口卡片，再部署。

图片、PDF 等附件也需要登记到同一清单的 `assets` 数组。尽量交付自包含 HTML；若依赖其他文件，也要登记并验证链接。

## 4. 检查并同步

在终端执行：

```bash
cd /home/hao/Desktop/HaoLifeOS/Personal_Website
./pw_deploy.sh sync --apply
```

程序先验证发布标记、临时构建、核对草稿和 HTML 发布范围，通过后才同步本地网站。它不会提交、推送或上线，也不会改写 Obsidian 原文。

可选：`./pw_deploy.sh plan` 只看差异；`./pw_deploy.sh` 检查和临时构建，不同步。

遇到未知文件、缺少标记、链接冲突、目标文件独立修改或构建失败时停止，把报错交给维护者处理。不要强制覆盖、重置或删除原文。

## 5. 本地预览

同步通过后运行：

```bash
cd /home/hao/Desktop/personal_website-quartz5
./publishing/preview.sh
```

打开 [本地预览](http://127.0.0.1:8885/personal_website/)。它先构建网站目录中已同步的内容，再启动本地服务；本地预览关闭生产统计。

- 核对文章内容、标题和标签。
- 确认草稿文章未公开。
- CS6515：实际点击新卡片，检查英文默认、中英文切换、下一步或播放按钮，以及手机宽度下的布局。

预览不会自动同步或刷新 Obsidian 修改。再次编辑后，先同步，再在预览终端按 `Ctrl+C` 停止服务、重新运行预览脚本。重启电脑后也需重新启动。若端口仍被占用，可以运行 `./publishing/preview.sh 8886` 并访问对应端口。

普通预览隐藏草稿。未准备公开的 HTML 可先直接在浏览器打开原文件；需要检查完整站点中的草稿时，另建隔离预览，不把正式发布标记当成临时开关。

## 6. 正式上线

推荐做法：本地检查通过后，告诉维护者“本地检查通过，部署这次更新”，再由维护者检查差异、提交和部署。

自行发布时，在网站仓库确认当前分支为 `codex/quartz5`，并检查改动：

```bash
cd /home/hao/Desktop/personal_website-quartz5
git branch --show-current
git status --short
git diff -- content publishing/assets.json
git add -- content publishing/assets.json
git commit -m "Update notes and CS6515 reviews"
git push origin codex/quartz5
```

**最后一条推送会触发正式部署。** 不在父级 HaoLifeOS 内容仓库中执行网站发布，不用 `git add .` 混入其他改动。如果分支不符、出现冲突或推送被拒绝，停止并处理原因，不强制推送。

以上命令只暂存文章和资源清单。涉及网站配置、布局或样式的功能改动，需要额外审核并明确暂存对应文件；例如本次赞助页脚不只是文章变动，不直接套用纯内容发布命令。

## 7. 上线后验收

| 检查项 | 通过条件 |
|---|---|
| [GitHub Actions](https://github.com/HaoLiangPao/personal_website/actions) | 本次提交的 build、deploy 都成功 |

| CS6515 | 卡片打开正确页面，语言切换和互动正常 |
| 旧链接 | 已有文章入口继续可访问或正确跳转 |

与文件夹同名的草稿可能对应一个正常的目录导航页；该页只展示已发布条目，不代表草稿正文上线。

## 8. 托管与 Observability（访问、点击和运行状态）

### 网站由谁运行

**Obsidian 原文 → 本地同步与预览 → 推送网站仓库 → GitHub Actions 检查构建 → GitHub Pages 托管。**

| 服务 | 当前职责 |
|---|---|
| 本机 Obsidian | 编辑文章、管理草稿和 HTML 批准清单 |
| Quartz 5 | 把 Markdown、配置和资源生成静态网站；它是构建工具，不是在线托管商 |
| GitHub 仓库 | 保存网站代码、同步后的内容和版本记录 |
| GitHub Actions | 推送 `codex/quartz5` 后执行测试、发布范围检查、构建和部署 |
| GitHub Pages | 对外提供正式网站的 HTML、CSS 和 JavaScript；关机不影响已上线的网站 |
| Google Analytics 4（GA4） | 接收浏览器上报的访问和互动事件 |
| Buy Me a Coffee | 提供赞助页面与收款记录；付款在平台上完成 |

目前不需要自己租服务器。个人网站是静态站点，没有网站自己的登录系统、数据库或可接收 Webhook 的后端。评论区的 GitHub 登录不等于网站访客身份系统。

### 当前统计接入与本次核验

核验日期：2026-10-28。

| 项目 | 当前结论 |
|---|---|
| GA4 Measurement ID | `G-6GTVSFXCB1`，与后台 `Personl Websites` 数据流一致 |
| 后台开关 | Enhanced measurement 与 Outbound clicks 已开启；本次只读查看，没有修改设置 |
| 正式站基本接入 | Google 标签成功加载；观察到 `page_view` 收集请求返回 HTTP 204；后台数据流显示过去 48 小时正在收数 |
| 赞助点击 | 正式统计配置的本地诊断构建中，页脚、CS6515 英文和中文入口均生成 `click`，`link_domain=buymeacoffee.com`，`outbound=true` |
| 本地测试边界 | 诊断时拦截 GA 收集请求，不把本地赞助测试写入正式统计；新按钮尚未部署，后台正式报表的按钮点击仍需上线后验收 |
| 日常预览 | `./publishing/preview.sh` 关闭 GA，预览时不会真实上报访问或点击；预览没有事件是正常现象 |
| 三个独立互动 HTML | 尚未接入 GA，不统计它们自身的浏览、语言切换或步骤操作；入口文章中的外链统计与此分开 |

HTTP 204 表示收集接口接受了请求，不等于该事件已出现在最终报表。正式报表可能延迟，统计也受浏览器、拦截器、同意设置和数据过滤影响。

### 怎样查看赞助点击

1. 打开 [Google Analytics](https://analytics.google.com/)，选择对应属性；当前属性名称是 `fir-learn-62666`。以数据流 URL 和 Measurement ID 核对，避免选到其他属性或演示数据。
2. 在“管理 → 数据收集和修改 → 数据流”打开 `Personl Websites`，确认 URL 是正式网站、编号是 `G-6GTVSFXCB1`，且增强衡量中的出站点击已开启。不要为检查而随意改动其他开关。
3. 上线后访问正式网站并实际点击赞助链接。在“报告 → 实时概览”查看 `click`；核对参数 `link_domain`、`link_url` 和来源页面。后台确认前，不把前端发请求称为最终报表已收录。
4. 长期查看时，在“探索 → 自由形式”使用事件名、Link domain、Link URL、Page location 等维度和 Event count 指标。筛选 `Event name = click`、`Link domain = buymeacoffee.com`，再按链接网址和页面位置细分。

链接保留这些来源参数：

| 参数 | 值 / 用途 |
|---|---|
| `utm_source` | `personal_website` |
| `utm_medium` | `referral` |
| `utm_campaign` | `support` |
| `utm_content=footer` | 来自全站页脚 |
| `utm_content=cs6515-en` | 来自课程英文入口 |
| `utm_content=cs6515-zh` | 来自课程中文入口 |

页脚链接 ID 是 `support-footer`；课程入口还有 `support-cs6515-en` / `support-cs6515-zh` 两个链接 ID，可在 `link_id` 中区分。赞助入口均在新标签页打开，保留当前阅读位置。UTM 是来源标签，本身不收集数据；在本网站 GA 中通过出站事件的 `link_url` 查看它，不把它误当成本站的流量获取来源。

目前复用 GA4 原有的自动 `click` 事件，没有额外的 `support_click` 事件，因此同一次赞助点击不用把两类事件相加。

### 能看见什么、还需要什么

| 想了解的内容 | 当前办法与限制 |
|---|---|
| 浏览量、热门文章、访客来源、设备与地区概况 | 现有 GA4；人数是分析口径，不代表可识别的真实姓名 |
| 赞助链接点击次数与入口 | 上述 GA4 出站事件；点击次数不等于独立人数，也不等于完成付款 |
| 访客的真实姓名、邮箱或 GitHub 身份 | 当前不会自动获得；不向 GA 发送个人身份信息 |
| 实际赞助、金额和退款 | 查看 Buy Me a Coffee 后台提供的记录；本站点击统计不证明到账 |
| 赞助平台页面的浏览 | Buy Me a Coffee 支持单独配置 GA；当前未代用户修改平台设置 |
| 自动同步到账或退款 | 后续可使用平台 Webhook，需要额外服务端接收、验签、去重和私有存储；当前未配置 |
| 网站打不开时主动通知 | 需要另设外部可用性监测；Actions 成功只证明本次流水线成功 |
| 页面脚本报错自动告警 | 需要另加前端错误监测；GA4 访问统计不替代错误告警 |

### 发布前后的统计检查

- 本地：链接位置、英语默认和中文切换、目标 URL、手机布局通过；普通预览保持关闭生产统计。
- 上线后：正式站点点击按钮，确认 GA4 的目标域名、来源页面与 `utm_content`，再核对后台实时事件和后续报表。
- 故障排查：先核对 Measurement ID 和后台开关，再看浏览器是否发出请求、是否被拦截，最后检查数据过滤与报表延迟。不要把“没有访问”直接判成“网站宕机”。
