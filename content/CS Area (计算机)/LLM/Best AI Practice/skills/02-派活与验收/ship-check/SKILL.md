# 验收与上线

**子代理说它跑过了不算数，自己跑过才算数。** 任何一关不过就打回。

## 一、亲自验收
1. 跑测试：全绿，且总数不少于上一轮。
2. 跑 build 和 lint：零错误。
3. 看范围：`git diff --stat HEAD -- <禁改目录>` 必须为空，`git status --short` 与报告一致。
4. 跑文档索引和 frontmatter 检查。
5. 亲手走关键路径：用浏览器走真实流程，留截图，console 零 error。
6. 逐条处理「自主决定」：接受 / 要求改 / 记入台账，不许略过。

验收的本质是找它没说的东西。报告说「隔离没问题」，要验的是「B 改 A 的数据是否 0 行生效」。

## 二、独立审核
非琐碎改动交给 `code-guardian`。阻塞和应修项都要修，最多 2 轮。没有 `PASS` 就不说「审核通过」。

## 三、提交
一个单元一个 commit。正文写：为什么做 / 谁实现 / 谁验收 / 验收证据。只 `git add` 自己的文件。

## 四、QA 复检（涉及上线时）
派独立 QA，要求分级缺陷和明确的 Go/No-Go。范围包括回归、新流程、移动视口和 console。

## 五、部署
按阶段走，每步的权限看项目的授权表：
1. 推送后看**远端 CI** 的结果，不看本机。本机绿不等于 CI 绿。
2. 部署预览并冒烟。
3. 预构建生产，不切流量，得到待发布地址。
4. 人类批准后切换。这一步秒级完成，也能秒级回滚。

数据库迁移要先于依赖它的代码上线；改写或删除已有数据的迁移每次都要单独批准。

## 六、上线后亲自冒烟
在生产环境走一遍：游客主流程 + 测试账号登录 + console。不要因为 QA 说 Go 就省略。

## 七、收尾
走 `round-closeout`。
