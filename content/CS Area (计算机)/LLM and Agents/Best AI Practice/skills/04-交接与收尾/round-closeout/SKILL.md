# 收尾与交接

历史上的质量事故常常可以追溯到「跳过验收」或「跳过收尾」。

## 清单
- [ ] 报告：交付了什么（对应 commit）、偏差和自主决定、验证证据、花费结构。
- [ ] 状态：上线的 design 转 `implemented`，被取代的转 `superseded`，`proposed` 的 ADR 进台账。
- [ ] 台账：删除已办项并留去向，加入新项，逐条核对仍成立。
- [ ] **交接笔记：改写「现在到哪、下一步、新踩的坑」，并写上更新日期。** 过期的交接笔记比没有更危险。
- [ ] 讨论中的共识：另一个会话里的决定也要落文档。没落文档就等于下个会话不知道。
- [ ] 把未推送的 commit 数和线上版本写清楚。
- [ ] 运行文档检查。

## 汇报格式
先结论，再细节，最后列「需要你做什么」，然后附表：

| 步 | 内容 | 执行 | 产出 | 改动 |
| -- | ---- | ---- | ---- | ---- |
| S3 | 归档数据模型 | CTO (Opus) | ADR + 迁移 + 6 个文件 | +412 −38，新增 21 测试 |

改动量用 `git diff --shortstat` 的真实数字，不许估。被打回的也写。

## 什么时候换会话
上下文已经很长时就换。仓库要做到新会话读规则、手册和交接笔记即可开工，而不是靠续聊记忆。
