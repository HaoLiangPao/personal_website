# 合成 pilot

## 两种代理，不要混用

| | A. 探索型测试员 | B. 数据型驱动器 |
| - | -------------- | -------------- |
| 实现 | LLM 子代理（QA），像人一样操作 | 脚本，每一步不调 LLM |
| 找什么 | 缺陷、卡壳、看不懂的文案 | 学习曲线、数据完整性、指标 |
| 规模 | 每个 persona 1 次完整会话 | 每个 persona 30 个模拟日 |

**学习效果只拿脚本里写死的真实偏好来度量。** LLM 说「这家不错」不代表任何用户的真实看法。

## 步骤
1. **先定要回答的问题**，例如「第几天开始摇出喜欢的店」。
2. **隔离数据**：专用账号命名，并提供一条 SQL 就能与真人分开的视图。
3. **设计 persona**：包括「强烈偏爱一整类」的极端用户。离线模拟常常漏掉这类用户。
4. **定配额上限**：外部 API 调用次数写进设计文档，脚本默认拦截自动调用。
5. **预检工具**：浏览器起不来时，LLM 测试员会白白烧 token。
6. **驱动器要能自愈**：每天检查并重建页面，每个 persona 单独进程，支持断点续跑。
7. **核对**：驱动器记录的动作和数据库逐条比对。
8. **分析**：拆开打分因子，回答「为什么推不准」，而不只说「推不准」。

## 报告必须有
结论、学习曲线、分级缺陷（附根因，由主驾驶核实）、可观测性缺口、花费。

每一个「想回答却回答不了」的问题，都是一条可观测性缺口。

## 注意
- 合成数据不能证明用户喜欢产品，它只能在真人到来前排雷。
- 页面快照可能输出口令明文，报告里不要带。
- 在生产环境运行要先得到人类批准。
